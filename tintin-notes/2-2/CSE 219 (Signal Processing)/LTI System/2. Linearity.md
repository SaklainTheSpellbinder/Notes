# Module 2: Linearity

## The core idea, explained properly

Linearity is really **two separate promises** bundled together. Let's take them one at a time, because conflating them is where people get sloppy.

### Promise 1: Scaling (Homogeneity)

If you know that $x(t) \to y(t)$, then scaling the input by any constant $a$ _must_ scale the output by that exact same constant:

$$a,x(t) \longrightarrow a,y(t)$$

Think of it as: **the system has no "opinion" about amplitude.** Whatever it does to a signal, it does proportionally. If you play a song twice as loud into an amplifier (that's genuinely linear), you get exactly twice the output amplitude — not louder-than-double, not saturated, not "a different sound." Real-world violation: an overdriven guitar amp or a clipping speaker — play it too loud and the output isn't just "louder," it distorts. That's your intuition for _nonlinearity_: distortion, saturation, "diminishing returns," anything where doubling the input doesn't cleanly double the output.

### Promise 2: Additivity (Superposition)

If $x_1(t) \to y_1(t)$ and $x_2(t) \to y_2(t)$ separately, then feeding the _sum_ $x_1(t)+x_2(t)$ into the system gives you exactly the _sum_ of the individual outputs:

$$x_1(t) + x_2(t) \longrightarrow y_1(t) + y_2(t)$$

This is the deep one. It says: **the system can't "tell" that two signals are mixed together** — it processes each contribution independently and the results just stack. This is why, in a concert hall, you can (to good approximation) think of the echo from the violin and the echo from the trumpet as two separate, independent echoes added together — the room doesn't "combine" them into some new weird sound; it treats each source's sound as if the other weren't there.

### Combining both: the superposition principle

Putting scaling and additivity together gives the single test used in practice:

$$a,x_1(t) + b,x_2(t) \longrightarrow a,y_1(t) + b,y_2(t)$$

for **any** constants $a, b$ and **any** signals $x_1, x_2$. This is _the_ definition of linearity you check on an exam. To prove a system is linear, you must show this holds for arbitrary $a,b,x_1,x_2$ — not just for one example pair. To prove a system is _not_ linear, one single counterexample is enough to kill it.

## The hidden consequence people forget: zero-in, zero-out

Here's a freebie that follows immediately from the scaling property, and it's a favorite trick in exams: set $a = 0$.

$$0 \cdot x(t) \longrightarrow 0 \cdot y(t) \implies x(t) = 0 \longrightarrow y(t) = 0$$

**Every linear system must map the all-zero input to the all-zero output.** If someone hands you a system where feeding in "nothing" produces "something" (a nonzero output), that system is instantly disqualified from being linear — no further checking needed.

⚠️ **But be careful of the converse trap:** zero-in-zero-out is a _necessary_ condition for linearity, not a _sufficient_ one. Plenty of nonlinear systems still satisfy zero-in-zero-out. Example: $y(t) = x(t)^2$. Plug in $x(t)=0$, you get $y(t)=0$ — passes the freebie test — but it's still not linear (we'll show why below). So this test can only be used to quickly _reject_ systems, never to _confirm_ linearity.

## Worked examples (the kind that actually build intuition)

**Example A — Linear:** $y(t) = 3x(t)$. Check: $a x_1 + b x_2 \to 3(ax_1+bx_2) = a(3x_1) + b(3x_2) = a y_1 + b y_2$. ✓ Linear.

**Example B — Looks linear, isn't:** $y(t) = 2x(t) + 5$.

This is the classic trap. In algebra class, "$y = 2x+5$" is called a **linear equation** (it graphs as a straight line). But as a _system_, it is **not linear**! Check zero-in-zero-out: $x(t)=0 \Rightarrow y(t) = 5 \ne 0$. Fails instantly. The extra additive constant ("offset" or "bias") breaks superposition — this is technically called an **affine** function, not a linear one. This exact distinction ("straight line on a graph" ≠ "linear system") is one of the most common exam gotchas in signals courses.

**Example C — Nonlinear (nonlinearity via power):** $y(t) = x(t)^2$.

Check scaling: input $ax(t)$ gives output $(ax(t))^2 = a^2 x(t)^2 = a^2 y(t)$. But linearity demands the output scale by exactly $a$, not $a^2$. Unless $a^2 = a$ for all $a$ (false, e.g. $a=2$ gives $4 \ne 2$), this fails. Not linear.

**Example D — Linear even though it's "weird":** $y[n] = n \cdot x[n]$.

This might feel like it shouldn't be linear because of the "$n$" sitting there. But check the definition directly: $$a x_1[n] + b x_2[n] \xrightarrow{\text{system}} n\big(a x_1[n] + b x_2[n]\big) = a\big(n x_1[n]\big) + b \big(n x_2[n]\big) = a y_1[n] + b y_2[n]$$ ✓ This **is** linear! The multiplier $n$ changes with time, but at _each fixed time_ $n$, the relationship between input value and output value is still a straight proportional scaling — just a different proportionality constant at each time step. (Spoiler for Module 3: this system will turn out to be linear **but not time-invariant** — this is exactly the kind of system that shows you linearity and time-invariance are two totally separate properties, and you need _both_ to get an LTI system.)

**Example E — Nonlinear via multiplying two signals together:** $y[n] = x[n]\cdot x[n-1]$.

Try $x_1[n] = \delta[n]$ (giving some output $y_1[n]$) and $x_2[n] = \delta[n-1]$ (giving some $y_2[n]$), then compare $x_1+x_2$ processed together vs. $y_1+y_2$ added afterward — you'll find they disagree once cross-terms appear (this is essentially "$(A+B)^2 \ne A^2+B^2$" flavor of failure — multiplying two copies of the signal together always breaks additivity, because of the cross term). We'll make you carry this out explicitly in the exercises.

## Quick decision checklist (use this on the exam)

1. **First, try the zero-input freebie.** If $x(t)\equiv 0$ doesn't give $y(t) \equiv 0$, stop — not linear.
2. **Then check scaling.** Replace $x$ with $ax$ symbolically. Does the output become exactly $a \times$(original output)? If any power, square root, absolute value, max, or constant offset appears, it usually breaks here.
3. **Then check additivity.** Plug in $x_1+x_2$ and see if it equals $y_1+y_2$ term by term. Watch especially for **products of the signal with itself** (like $x[n]x[n-1]$, $x(t)^2$) — multiplication of the unknown signal by _itself_ (as opposed to multiplication by a fixed, known function of time) is the single most common source of nonlinearity.
4. If it survives all of this for arbitrary $a,b,x_1,x_2$ — it's linear.

## Exercises — Module 2 (with answers)

**1.** Determine whether each system is linear. Give a full proof if linear (general $a,b,x_1,x_2$), or one explicit counterexample if not.

(a) $y[n] = x[n] - x[n-1]$ (b) $y(t) = |x(t)|$ (c) $y[n] = x[2n]$ (downsampling — keep only even-indexed samples) (d) $y(t) = x(t)\cos(t)$ (e) $y[n] = x[n] + x[-n]$

**2.** A student claims: _"Since $y(t) = \dfrac{d}{dt}x(t)$ involves calculus, and calculus is 'complicated,' this system can't be linear."_ Prove the student wrong: show explicitly, using the properties of derivatives, that differentiation **is** a linear system.

**3. (The cross-term trap.)** Consider $y[n] = x[n]\cdot x[n-1]$ from Example E above. Let $$x_1[n] = \delta[n], \qquad x_2[n] = \delta[n-1]$$ (a) Compute $y_1[n]$ (output from $x_1$ alone) and $y_2[n]$ (output from $x_2$ alone), for all $n$. (b) Compute $y_1[n]+y_2[n]$. (c) Now compute the actual output when the combined input $x_1[n]+x_2[n]$ is fed into the system directly. (d) Compare (b) and (c) and state clearly why they differ — pin down exactly which term causes the mismatch.

**4.** Is the system $y(t) = x(t-2) + 4$ linear? Justify using the zero-input test **first**, before doing any other check, and explain why that's the fastest route to the answer here.

## Answers

**1(a)** Linear. Let $x = a x_1 + b x_2$. Then $$y[n] = (ax_1[n]+bx_2[n]) - (ax_1[n-1]+bx_2[n-1]) = a(x_1[n]-x_1[n-1]) + b(x_2[n]-x_2[n-1]) = ay_1[n]+by_2[n]$$ ✓

**1(b)** Not linear. Scaling test: input $-x(t)$ gives output $|-x(t)| = |x(t)|$, i.e., the output is _unchanged_ by negating the input, but linearity would require it to become $-|x(t)|$ (i.e. $a=-1$ should give $a\cdot y(t)$). E.g. with $x(t)=5$: original output is $5$; scale input by $a=-1$ to get $x=-5$, output is $|-5|=5$, but linearity demands $a\cdot y = -1\cdot 5 = -5 \ne 5$. Fails.

**1(c)** Linear. $y[n] = x[2n]$ is just sampling at even indices — a purely selective/rearranging operation with no distortion of amplitude. For $x = ax_1+bx_2$: $y[n] = a x_1[2n] + b x_2[2n] = a y_1[n] + b y_2[n]$. ✓ (Note: like Example D, this will later turn out to be linear but **not** time-invariant.)

**1(d)** Linear. $\cos(t)$ is a _fixed, known_ function of time (not dependent on the input), so this is just "multiply by a known time-varying gain" — same structure as Example D. $y(t) = (ax_1(t)+bx_2(t))\cos(t) = a(x_1(t)\cos t) + b(x_2(t)\cos t) = ay_1(t)+by_2(t)$. ✓

**1(e)** Linear. $y[n] = (ax_1[n]+bx_2[n]) + (ax_1[-n]+bx_2[-n]) = a(x_1[n]+x_1[-n]) + b(x_2[n]+x_2[-n]) = ay_1[n]+by_2[n]$. ✓ (Adding a time-reversed copy is still a linear combination operation.)

**2.** For any differentiable signals $x_1(t), x_2(t)$ and constants $a,b$, the sum rule and constant-multiple rule of differentiation state: $$\frac{d}{dt}\big[a x_1(t) + b x_2(t)\big] = a\frac{d x_1(t)}{dt} + b\frac{dx_2(t)}{dt} = a,y_1(t) + b,y_2(t)$$ This is literally a basic theorem from calculus — it holds for _all_ differentiable $x_1,x_2$ and _all_ constants $a,b$, which is exactly the superposition test. So differentiation is linear (in fact it's a foundational example of a linear operator in all of mathematics, not just signals).

**3.** (a) $x_1[n]=\delta[n]$ is nonzero only at $n=0$ (value 1), zero elsewhere. So $x_1[n-1]$ is nonzero only at $n=1$. Their product $y_1[n] = x_1[n]x_1[n-1]$ requires _both_ factors nonzero at the same $n$ — impossible (nonzero at $n=0$ for one factor, $n=1$ for the other, never both at once). So $y_1[n] = 0$ for all $n$.

Similarly, $x_2[n] = \delta[n-1]$ is nonzero only at $n=1$; $x_2[n-1]$ nonzero only at $n=2$ — again never simultaneously nonzero. So $y_2[n] = 0$ for all $n$.

(b) $y_1[n] + y_2[n] = 0$ for all $n$.

(c) Combined input: $x[n] = x_1[n]+x_2[n] = \delta[n] + \delta[n-1]$, i.e., $x[0]=1, x[1]=1$, zero elsewhere.

Compute $y[n] = x[n]\cdot x[n-1]$ directly:

- $n=1$: $x[1]\cdot x[0] = 1 \cdot 1 = 1$
- all other $n$: at least one factor is $0$.

So $y[n] = \delta[n-1]$, i.e., $y[1] = 1$, all else $0$.

(d) Comparing: (b) gives all-zero, but (c) gives a nonzero value at $n=1$. **They disagree at $n=1$.** The culprit is exactly the _cross term_: when you expand $(x_1[n]+x_2[n])(x_1[n-1]+x_2[n-1])$, you get four terms: $x_1[n]x_1[n-1] + x_1[n]x_2[n-1] + x_2[n]x_1[n-1] + x_2[n]x_2[n-1]$. The first and last terms are $y_1[n]$ and $y_2[n]$ individually (both zero here), but the **middle cross-terms** ($x_1[n]x_2[n-1]$ and $x_2[n]x_1[n-1]$) are extra contributions that only exist when both signals are present _simultaneously_ — and it's precisely one of these cross terms that produces the nonzero value at $n=1$. This is the mathematical fingerprint of nonlinearity: multiplying the unknown signal by itself always generates these uncancelled cross terms.

**4.** Zero-input test: set $x(t) \equiv 0$. Then $y(t) = 0 + 4 = 4 \ne 0$. **Fails immediately — not linear.** This is the fastest check here because the system has an obvious additive constant ("$+4$") sitting outside the input-dependent part; any such fixed offset guarantees zero input won't produce zero output, so there's no need to even attempt the full scaling/additivity check — one line kills it.

## The key point: "x(t) = 0" means the _whole signal_ is zero — everywhere, for every possible argument

When we say "test with $x(t) \equiv 0$," we're not saying "plug in the number $t$ into $x$ and get 0 at that one instant." We're declaring an entire input **signal**: a function that outputs $0$ no matter what you feed into it. It's zero at $t=5$, zero at $t=-100$, zero at $t=2$, zero at $t-2$ for _any_ $t$ — literally zero at every real number you could possibly plug in as its argument.

So when the system formula asks for $x(t-2)$, we're not doing anything new or making an extra choice — we're just evaluating that _same_ zero-signal at the point $(t-2)$ instead of at the point $t$. Since the signal is zero **everywhere**, it doesn't matter what argument you stick in:

$$x(\text{anything}) = 0 \quad \text{whenever } x \equiv 0$$

So $x(t-2) = 0$ automatically — not because we're "choosing" it, but because there's nothing else it _could_ be, given that $x$ is the all-zero function.

## Why you don't need $y(t-2)$

Your instinct to ask about $y(t-2)$ suggests you might be thinking: _"the input got shifted, so shouldn't I track the output at a shifted point too?"_ That instinct is exactly right for a **different** test — the _time-invariance_ test (Module 3, coming up next) — where we compare $y(t-t_0)$ against the response to a shifted input. But for the **linearity** (zero-in-zero-out) test, there's no shifting comparison happening at all. We just want to know one thing:

> _"If I feed in the zero signal, do I get the zero signal out — at every point $t$?"_

So we directly compute $y(t)$ (not $y(t-2)$) for a general $t$, using the system's own formula:

$$y(t) = x(t-2) + 4 = \underbrace{0}_{\text{since } x \equiv 0} + 4 = 4$$

This holds for **every** $t$ you plug in — so the output signal is the _constant_ signal $y(t) = 4$, which is clearly not the zero signal. That's the violation. No need to ever reference $y(t-2)$; we just needed to show _some_ output value is nonzero when the whole input is zero, and evaluating at plain $t$ does that immediately.

## The general lesson (useful beyond this problem)

Any system built purely from **time-shifts, scalings, reversals, or reorderings** of $x$ (like $x(t-2)$, $x(2t)$, $x(-t)$, $x(t+5)$...) will _always_ map the zero signal to the zero signal — because shifting/scaling/flipping a function that's zero everywhere still gives you zero everywhere. There's no substitution trick that can turn "always 0" into "sometimes nonzero."

The **only** way zero-in-zero-out fails is if the system formula has something added on that _doesn't_ depend on $x$ at all — like that lone "$+4$" sitting there. That standalone constant survives even when the entire $x$-dependent part collapses to zero, and that's what breaks linearity. This is a good pattern-recognition shortcut: **any bare additive constant in a system's formula is an automatic linearity killer**, regardless of what happens to $x$ elsewhere in the formula.
