# Module 3: Time-Invariance

## The core idea, explained properly

Linearity (Module 2) was about **amplitude** — "does the system treat scaling and adding of signals fairly?" Time-invariance is a completely separate question, about **timing** — "does the system care what the calendar says?"

Formally:

$$\text{If } x(t) \longrightarrow y(t), \text{ then } x(t-t_0) \longrightarrow y(t-t_0), \text{ for every } t_0.$$

In plain English: **if you delay the input by $t_0$ seconds, the only thing that happens to the output is that it also gets delayed by exactly $t_0$ seconds — nothing else about it changes.** Same shape, same amplitude, same behavior — just shifted later (or earlier) on the time axis.

## The intuition: does the system have a "personality" that changes over time?

Think of a **guitar pedal**. If you play a riff today, and record the output, then play the _exact same riff_ tomorrow, you expect the _exact same output sound_ — just happening a day later. The pedal doesn't "know" what day it is; its behavior is the same regardless of when you feed it a signal. That's time-invariance.

Now contrast with a **thermostat-controlled system whose gain changes with the time of day** — say, the system amplifies by a factor of 2 during the "day" and by a factor of 0.5 at "night." If you play a signal at noon (gain ×2) vs. the identical signal at midnight (gain ×0.5), you get _different-shaped outputs_, not just the same output shifted in time. This system has an internal clock baked into its rule — it's **time-varying**, not time-invariant.

The slides' visual (Mr. Bean speeding up / slowing down) captures this nicely: whether you clip the _input video_ early or late, the _processing itself_ (blur, whatever effect) behaves identically — only the position in time of the result changes.

## How to actually test it (the mechanical procedure)

This is the part that trips people up, so let's be very explicit about the recipe. To check time-invariance for a system rule $y(t) = (\text{some formula involving } x)$, you do **two separate things** and compare them:

**Path 1 — "Delay the output":** Take the _original_ output formula $y(t)$, and everywhere you see $t$, replace it with $(t - t_0)$. Call this $y(t-t_0)$.

**Path 2 — "Delay the input first, then run the system":** Define a new input $x_d(t) = x(t-t_0)$ (the delayed input). Plug _this_ $x_d$ into the _original system formula_ in place of $x$, and simplify. Call the result $y_d(t)$.

**Then compare:** If $y_d(t) = y(t-t_0)$ for all $t$ and all $t_0$ — time-invariant. If they differ — time-varying.

This "do it twice and compare" structure is exactly analogous to how you tested linearity by comparing "sum of outputs" vs. "output of the sum." Here you're comparing "shift the output" vs. "output of the shifted input."

## Worked examples

**Example A — Time-invariant:** $y(t) = 3x(t) + 1$ _(ignore that it's not linear — we're only testing time-invariance now, a completely separate property!)_

- Path 1: $y(t-t_0) = 3x(t-t_0) + 1$
- Path 2: input $x_d(t) = x(t-t_0)$, so $y_d(t) = 3x_d(t)+1 = 3x(t-t_0)+1$
- Same! ✓ Time-invariant.

**Example B — Time-varying:** $y(t) = t\cdot x(t)$ _(this is our old friend from Module 2 — remember, it was linear!)_

- Path 1: $y(t-t_0) = (t-t_0),x(t-t_0)$
- Path 2: $x_d(t) = x(t-t_0)$, so $y_d(t) = t\cdot x_d(t) = t\cdot x(t-t_0)$
- Compare: $(t-t_0)x(t-t_0)$ vs. $t\cdot x(t-t_0)$ — these differ (unless $t_0=0$)! ✗ **Not** time-invariant.

This is a great illustration of why linearity and time-invariance are genuinely _independent_ axes — $y(t)=tx(t)$ is linear but time-varying (multiplying by "$t$" is a fair, proportional operation at each instant, satisfying linearity, but the _multiplier itself_ changes as the clock ticks, so shifting the input in time doesn't just shift the output — the "$t$" in front stays anchored to the _original_ clock, not to the new position of the signal).

**Example C — Time-varying (downsampling):** $y[n] = x[2n]$

- Path 1: $y[n-n_0] = x[2(n-n_0)] = x[2n - 2n_0]$
- Path 2: $x_d[n] = x[n-n_0]$, so $y_d[n] = x_d[2n] = x[2n - n_0]$
- Compare: $x[2n-2n_0]$ vs. $x[2n-n_0]$ — different unless $n_0=0$! ✗ Not time-invariant.

Intuition: downsampling only keeps _even-indexed_ samples according to the _original_ numbering. If you shift the input by an odd amount, the sample that used to land on an "even slot" might now land on an "odd slot" and get thrown away — so a delay in the input doesn't produce a cleanly delayed output; it can produce a _completely different_ selection of samples. (This is exactly why, again, this system was linear in Module 2 but is time-_varying_ here — reinforcing that the two properties are unrelated.)

**Example D — Time-invariant:** $y[n] = x[n] - x[n-1]$ (a difference operator, like a discrete derivative)

- Path 1: $y[n-n_0] = x[n-n_0] - x[n-n_0-1]$
- Path 2: $x_d[n]=x[n-n_0]$, so $y_d[n] = x_d[n]-x_d[n-1] = x[n-n_0] - x[n-1-n_0]$
- Same! ✓ Time-invariant.

## The general pattern-recognition rule

- If the system's formula explicitly contains the **bare time variable "$t$" or "$n$"** appearing _outside_ of the argument of $x$ (like $t\cdot x(t)$, or $y[n]=x[n]/n$) → almost always **time-varying**, because that bare $t$ or $n$ acts like an internal clock that doesn't shift along with the signal.
- If the system's formula involves the input's argument being **rescaled** (like $x[2n]$, $x(t/2)$) rather than just **shifted** → almost always **time-varying**, for the reason shown in Example C (scaling and shifting don't commute nicely).
- If the system only involves **fixed shifts of the argument** combined with linear-in-$x$ combinations (like $x(t-3)$, $x[n]+x[n-1]$, $2x(t-1)-x(t-5)$) → typically **time-invariant**.

## Answers

**1(a)** Path 1: $y(t-t_0) = x(t-t_0-5)$. Path 2: $x_d(t)=x(t-t_0)$, so $y_d(t) = x_d(t-5) = x(t-t_0-5)$. Same. ✓ **Time-invariant.**

**1(b)** Path 1: $y[n-n_0] = x[-(n-n_0)] = x[-n+n_0]$. Path 2: $x_d[n]=x[n-n_0]$, so $y_d[n]=x_d[-n] = x[-n-n_0]$. Compare: $x[-n+n_0]$ vs $x[-n-n_0]$ — different (unless $n_0=0$). ✗ **Time-varying.** (Reversal flips the direction of the shift too — delaying the input by $n_0$ ends up _advancing_ the reversed output by $n_0$ instead of delaying it.)

**1(c)** Path 1: $y(t-t_0) = x(3(t-t_0)) = x(3t-3t_0)$. Path 2: $x_d(t)=x(t-t_0)$, so $y_d(t) = x_d(3t) = x(3t-t_0)$. Compare: $x(3t-3t_0)$ vs $x(3t-t_0)$ — different (unless $t_0=0$). ✗ **Time-varying.** (Same rescaling issue as Example C.)

**1(d)** Path 1: $y[n-n_0] = (n-n_0)x[n-n_0] + x[n-n_0-1]$. Path 2: $x_d[n]=x[n-n_0]$, so $y_d[n] = n,x_d[n] + x_d[n-1] = n,x[n-n_0] + x[n-1-n_0]$. Compare first terms: $(n-n_0)x[n-n_0]$ vs. $n,x[n-n_0]$ — different (extra bare $n$ term uncancelled). ✗ **Time-varying.**

**1(e)** Path 1: $y(t-t_0) = x(t-t_0)\cos(t-t_0)$. Path 2: $x_d(t)=x(t-t_0)$, so $y_d(t) = x_d(t)\cos(t) = x(t-t_0)\cos(t)$. Compare: $x(t-t_0)\cos(t-t_0)$ vs $x(t-t_0)\cos(t)$ — different (the $\cos$ argument doesn't shift along with $x$). ✗ **Time-varying.**

**2.** System: $y(t) = x(t)p(t)$.

- Path 1: $y(t-t_0) = x(t-t_0),p(t-t_0)$.
- Path 2: $x_d(t) = x(t-t_0)$, so $y_d(t) = x_d(t),p(t) = x(t-t_0),p(t)$.

Setting these equal for **all** $t$ and **all** $t_0$: $$x(t-t_0)p(t-t_0) = x(t-t_0)p(t) \quad \forall t, t_0$$

Since this must hold for _arbitrary_ input signals $x$ (in particular, wherever $x(t-t_0)\ne 0$), we need $p(t-t_0) = p(t)$ for all $t$ and all $t_0$. A function that equals _every one of its own shifted versions_, for _every possible shift_, must be constant — if $p$ took two different values anywhere, some shift $t_0$ would misalign them. So $p(t) = c$ (a constant) is required. This confirms: **multiplying by a fixed time-varying function breaks time-invariance unless that function is literally constant** — this generalizes Example E from Module 3 ($p(t)=\cos t$, not constant → time-varying) and explains _why_ that happened.
