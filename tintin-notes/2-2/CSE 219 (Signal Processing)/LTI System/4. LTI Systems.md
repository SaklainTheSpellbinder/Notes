# Module 4: LTI Systems — The Magic Combination

## The core idea, explained properly

An **LTI system** is simply a system that satisfies _both_ properties from Modules 2 and 3, simultaneously:

$$\textbf{Linear:} \quad a,x_1(t) + b,x_2(t) \longrightarrow a,y_1(t) + b,y_2(t)$$ $$\textbf{Time-invariant:} \quad x(t-t_0) \longrightarrow y(t-t_0)$$

That's it — no new machinery, just "the system passes _both_ checks from the last two modules." But here's the thing worth pausing on: **these two properties are logically independent of each other**, as you've now seen concretely (Module 3, Example B: $y(t)=tx(t)$ is linear but time-varying; Module 3, Exercise 3(b)/(c): $x(t)^2$ and $x[n]x[n-2]$ are time-invariant but not linear). There are four possible combinations a system can fall into:

||Linear|Not Linear|
|---|---|---|
|**Time-Invariant**|**LTI** (the golden combination)|e.g. $y(t)=x(t)^2$|
|**Time-Varying**|e.g. $y(t) = t,x(t)$|e.g. $y[n] = n,x[n]x[n-1]$|

Only the top-left box is what this entire course cares about. Why do we obsess over exactly this combination and not, say, "just linear" or "just time-invariant" on their own? That's the real content of this module.

## Why LTI is special: the "one measurement unlocks everything" promise

Here's the actual payoff, stated as precisely as the slides intend but with the reasoning spelled out (this reasoning is fully built out in Modules 8–13, but you should understand _why_ it's true right now, at a conceptual level, before we grind through the derivation):

Imagine someone hands you a mystery LTI system in a black box. You're allowed to send in **exactly one** test signal and observe **exactly one** output. Question: which one test signal should you pick, if your goal is to be able to _predict the output for any conceivable future input_, without ever touching the box again?

Answer: **the impulse** — an infinitely short, infinitely sharp poke, $\delta(t)$ or $\delta[n]$ (this is Module 9's topic, coming soon). Once you know the system's response to _that one specific signal_ — call it $h(t)$, the **impulse response** — you can, in principle, compute the exact output for _any_ input whatsoever, without ever running the input through the actual system again. You just do some arithmetic (which will turn out to be convolution) using $h(t)$ and the new input.

**Why does this work only for LTI systems, and not for general systems?** Because of exactly the two properties combined:

- **Time-invariance** guarantees: if you know how the system responds to _one_ impulse (at time 0), you automatically know how it responds to an impulse at _any other_ time — it's just a shifted copy of the same response, $h(t-t_0)$. Without time-invariance, you'd need to test the system with an impulse _at every possible time_ separately, since the response could be different each time — an impossible, infinite amount of testing.
    
- **Linearity** guarantees: since _any_ signal can be thought of as built up from a huge (infinite) collection of tiny scaled, shifted impulses (we'll prove this precisely in Module 11), and since a linear system's response to a _sum_ of inputs is just the _sum_ of the individual responses, you can add up all those individually-known shifted-impulse responses to reconstruct the _total_ output — without ever needing to feed the _actual_ complicated signal through the real system. Without linearity, knowing the response to each little piece wouldn't tell you anything about the response to the _sum_ of the pieces, because superposition could fail (cross-terms, saturation, etc. — exactly the stuff that broke linearity in Module 2).
    

So: **time-invariance lets you clone the single known response to any time position; linearity lets you add up clones to build any signal's response.** Take away either property, and the "one test tells you everything" trick collapses.

## A concrete preview (don't worry about deriving this yet — just feel the shape of it)

Say you poke an LTI system with an impulse and observe $h[n] = {1, 0.5, 0.25, ...}$ (fading echoes, decaying by half each step — this is literally the $\alpha^n u[n]$ system from the slides, with $\alpha = 0.5$).

Now someone hands you a _completely different_, more complicated input, say $x[n] = {2, -1, 3}$ (three samples). You **never** need to run $x[n]$ through the actual system. Instead:

- Treat $x[n]$ as three separate impulses: $2\delta[n]$, $-\delta[n-1]$, $3\delta[n-2]$.
- By time-invariance, you already know the response to _each_ shifted impulse: it's just $h[n]$, shifted to that same position.
- By linearity, you know the response to each _scaled_ impulse: it's that shifted $h[n]$, scaled by the same amount.
- Add up all three shifted-and-scaled copies of $h[n]$ → that sum **is** the exact output $y[n]$.

This entire procedure — decompose into impulses, look up the known response, scale, shift, add — **is** convolution. That's the whole point of everything from here through Module 13: convolution isn't an arbitrary formula someone invented; it's the _unavoidable consequence_ of linearity + time-invariance, applied to the impulse decomposition of a signal.

## Why this matters practically (so it doesn't feel abstract)

This is why, in real engineering, people characterize audio equipment, room acoustics, control systems, communication channels, etc., by measuring their **impulse response** — literally by clapping in a room, or sending a sharp electrical spike into a circuit, and recording what comes back. If the system is (approximately) LTI, that _one_ recorded response is enough to predict how the system will react to _any_ sound or signal you throw at it afterward, forever — you never need to re-measure the whole system again for a new input. That's an enormous practical shortcut, and it only works because of the LTI guarantee.

## Answers

**1.** Time-invariance alone tells you the response to a shifted impulse is just a shifted copy of $h$ — but it says _nothing_ about what happens when you feed in a signal made of many impulses _added together_. Without linearity, the response to the sum of pieces might not equal the sum of the individual known responses (cross-terms, saturation, etc., as in Module 2), so even though you know the response to each isolated shifted impulse, you have no guarantee about the response to the _combined_ signal — the reconstruction step (the "add up the pieces" step) is exactly where the reasoning breaks.

**2.** This is exactly the trap flagged in Module 2: zero-in-zero-out is a **necessary** consequence of linearity, but it is **not sufficient** to prove linearity. A system like $y[n] = x[n]^2$ (or $x[n]x[n-1]$) satisfies zero-in-zero-out perfectly (plug in all-zero input, get all-zero output) but is still nonlinear, because it fails the actual superposition test (scaling/additivity) once you feed in _nonzero_ inputs — the cross-terms and squared terms break additivity even though the specific zero-input case looks fine. So the friend's claim uses an incomplete test; you must verify full superposition (general $a,b,x_1,x_2$), not just the zero-input special case, before trusting convolution.

**3.** (a) **LTI.** Linear: pure sum of fixed-shifted copies of $x$, scaled by constants (1 and 1) — passes superposition directly (same structure as Module 3 Exercise 3(d)). Time-invariant: only fixed shifts of $x$ appear, no bare $t$, no rescaling — passes the two-path test (same structure as Module 3 Exercise 1(a)/Example A).

(b) **Not LTI** — fails time-invariance. This is the "switch that turns on at $n=0$" system. Test: original response to $\delta[n]$ passes zero-in-zero-out and is in fact linear (it's $x[n]$ times a _fixed_ known signal $u[n]$, same structure as Module 3 Exercise 2 with $p[n]=u[n]$ — which is linear, since "multiply by a fixed function" is linear regardless of time-invariance). But it fails time-invariance precisely because Module 3 Exercise 2 showed multiplying by a fixed non-constant function ($u[n]$ is not constant — it's 0 before $n=0$ and 1 after) breaks the shift-matching test. Concretely: an impulse at $n=-1$ gets multiplied by $u[-1]=0$ and vanishes, while an impulse at $n=0$ gets multiplied by $u[0]=1$ and survives — so two impulses that are just shifted copies of each other produce completely different-shaped responses (one is zero, one isn't), which can never just be "the same response, shifted."

(c) **LTI.** Linear: scaling by fixed constant 2 and fixed shift by $+3$ — passes superposition. Time-invariant: pure fixed shift + fixed scale, same reasoning as Module 3 Exercise 1(a)/Exercise 3(e).

**4.** If the system is time-varying, then the crucial guarantee from this module — "an impulse at any other time gives _the same shape of response, just shifted_" — no longer holds. The measured $h[n]={1,1,1}$ only tells you what happens to an impulse arriving at time $n=0$ specifically; it says **nothing** about what happens to an impulse arriving at $n=5$, because the system's behavior might itself have changed by the time step 5 rolls around (recall Module 3's thermostat analogy — behavior depends on "what time it is," not just "how long ago the poke happened"). To predict the response to $\delta[n-5]$, you would need to **re-measure the impulse response starting specifically at $n=5$** — i.e., you'd need a whole _family_ of impulse responses, one for every possible starting time $n_0$, denoted something like $h[n, n_0]$ — which defeats the entire "one measurement is enough" promise that made LTI systems so powerful in the first place.
