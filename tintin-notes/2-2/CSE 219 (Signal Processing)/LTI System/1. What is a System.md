# Module 1: What Is a System?

## The core idea, explained properly

Think about the difference between these two questions:

**Question A:** "If I plug in x = 3 into f(x) = x², what do I get?" → You get one number: 9. Done. No history, no future, no context. Just plug and chug.

**Question B:** "If I play _this specific piece of audio_ into my guitar's reverb pedal, what comes out?" → You don't get "one number." You get an entire new waveform — a whole new sound, stretched out over time, that depends on the _entire_ shape of what you played, not just its volume at one instant.

That's the entire philosophical jump this course is asking you to make. In your earlier math life (calculus, algebra), you dealt with **functions**: one number goes in, one number comes out. Now you're dealing with **systems**: one _entire signal_ goes in, one _entire signal_ comes out.

Formally:

$$x(t) \xrightarrow{;S;} y(t) \qquad \text{(continuous time)}$$ $$x[n] \xrightarrow{;S;} y[n] \qquad \text{(discrete time)}$$

Here $S$ is not a number-cruncher — it's an **operator on signals**. You feed it a function (or a sequence), and it hands you back a different function (or sequence).

## Why this distinction actually matters (this is the part people skip)

Here's the subtlety that the slides gesture at with "whole signal in, whole signal out" but don't spell out explicitly — and it's exactly the kind of thing exam questions like to exploit:

**For an ordinary function, $y = f(x)$ at a specific point depends _only_ on the input at that same point.** Nothing else matters.

**For a system, $y(t_0)$ at a specific time $t_0$ can depend on the input at _other_ times too** — past values, future values, or even the input's _entire_ history. The output isn't computed instant-by-instant in isolation; it can depend on how the input behaves across all of time.

Let's make this concrete with examples, from "boring" to "interesting":

|System|Rule|Does $y(t_0)$ depend only on $x(t_0)$?|
|---|---|---|
|Amplifier|$y(t) = 3x(t)$|Yes — purely instantaneous|
|Squarer|$y(t) = x(t)^2$|Yes — instantaneous, but _nonlinear_ (we'll see why that matters in Module 2)|
|Delay line|$y(t) = x(t-3)$|**No** — output at time $t_0$ needs the input from 3 seconds _earlier_|
|Differentiator|$y(t) = \dfrac{dx}{dt}$|**No** — a derivative is a limit involving neighboring time points|
|Echo adder|$y[n] = x[n] + x[n-1]$|**No** — needs current _and_ previous sample|
|Moving average|$y[n] = \frac{1}{3}(x[n]+x[n-1]+x[n-2])$|**No** — needs a whole window of samples|
|Time reversal|$y[n] = x[-n]$|**No** — needs a sample from a completely different location|

Notice: most _interesting_ systems (the ones with "memory," like delays, echoes, filters) genuinely need more than a single instantaneous value of the input. That's precisely _why_ we can't just think of a system as "a function you apply pointwise." You have to think of it as something that acts on the _whole trajectory_ of the signal.

## The "black box" picture

The way to internalize this: imagine $S$ as a black box. You don't feed it one number at a time and get one number back. You feed the _entire_ input signal (its complete story, from $-\infty$ to $\infty$, or over whatever domain you care about) into the box, and the box hands you back the _entire_ output signal, already complete.

```
   x(t)                          y(t)
 (whole                        (whole
 signal)  ────▶ [ System S ] ────▶  signal)
```

This is subtle but important for later: when we eventually build up the convolution formula, we're going to _literally_ reconstruct an entire input signal from tiny pieces (impulses), push each piece through the system, and then reassemble the output. That only makes sense once you've accepted that a system operates on signals as whole objects, not sample-by-sample independently.

## Continuous vs. discrete — same idea, different domain

- **Continuous-time (CT):** $x(t)$ is defined for every real number $t$ (a continuum of time instants). Example: $x(t) = u(t)$, the unit step, going into a system $S$ producing some $y(t)$.
- **Discrete-time (DT):** $x[n]$ is defined only at integer indices $n$ (a sequence of samples). This is what you'll mostly code in your Python lab, since computers can't store a continuum — they store sequences.

Same conceptual picture, just different "clocks": one ticks continuously, the other ticks in discrete steps.

## Exercises — Module 1

These require actual reasoning, not just recall. Write out full justifications.

**1.** A classmate says: _"A system is basically the same thing as a function, just with a fancier name — because in both cases, if you know the value of $x$ at time $t_0$, you can find $y$ at time $t_0$."_

Is this claim true in general? Prove your answer is correct by giving **one explicit counterexample system** (define it mathematically), showing two different _entire_ input signals $x_1(t)$ and $x_2(t)$ that happen to agree at some time $t_0$ (i.e. $x_1(t_0) = x_2(t_0)$), but for which the corresponding outputs disagree at that same time $t_0$ (i.e. $y_1(t_0) \ne y_2(t_0)$).

**2.** Consider the discrete-time system defined by $$y[n] = x[n+1] - x[n-1]$$ (a) Is it possible to compute $y[0]$ using _only_ the value $x[0]$? Explain precisely what information is required.

(b) Given the input sequence $x[n] = n^2$ for all integers $n$, compute $y[n]$ as a closed-form expression in $n$ (not just a table of numbers).

**3.** Consider the CT system $y(t) = x(t)\cdot u(t)$, where $u(t)$ is the unit step ($u(t) = 1$ for $t \ge 0$, $u(t)=0$ for $t<0$).

Let the input be $$x(t) = \begin{cases} \sin(t) & t < 0 \ 2 & t \ge 0 \end{cases}$$

Write out $y(t)$ explicitly as a piecewise function, and explain in one sentence _what this system is physically doing_ to any input signal (i.e., what real-world operation does multiplying by $u(t)$ represent?).

**4. (The trap question.)** A system is defined as: _"the output at time $n$ equals the largest value the input has ever taken, up to and including time $n$"_ — i.e., $y[n] = \max_{k \le n} x[k]$.

(a) Compute $y[n]$ for $n = 0,1,2,3,4,5$ given $$x[n] = {3,\ -1,\ 5,\ 5,\ 2,\ 7} \quad \text{for } n = 0,1,2,3,4,5.$$

(b) Here's the trap: does this system have the property that $y[n]$ can be computed from $x[n]$ alone? Justify your answer carefully — and in doing so, explain why this system fundamentally _cannot_ be described by any formula of the form $y[n] = f(x[n])$ for some ordinary function $f$.

# Module 1 — Answers

**1.** Counterexample using the **delay system**: $y(t) = x(t-3)$.

Let $t_0 = 0$.

- $x_1(t) = 0$ for all $t$.
- $x_2(t) = 0$ for all $t \ne -3$, and $x_2(-3) = 5$.

These agree at $t_0=0$: $x_1(0) = x_2(0) = 0$.

But: $$y_1(0) = x_1(-3) = 0, \qquad y_2(0) = x_2(-3) = 5$$

So $y_1(0) \ne y_2(0)$ even though $x_1(0) = x_2(0)$. This proves the claim false — a system's output at $t_0$ can depend on input values far away from $t_0$, unlike an ordinary function.

**2.** $y[n] = x[n+1] - x[n-1]$

(a) No. Computing $y[0]$ requires $x[1]$ and $x[-1]$ — two neighboring samples, neither of which is $x[0]$ itself. In fact $x[0]$ doesn't even appear in the formula for $y[0]$.

(b) With $x[n] = n^2$: $$y[n] = (n+1)^2 - (n-1)^2 = (n^2+2n+1) - (n^2-2n+1) = 4n$$

**3.** $y(t) = x(t)\cdot u(t)$

Since $u(t) = 0$ for $t<0$ and $u(t)=1$ for $t\ge 0$:

$$y(t) = \begin{cases} 0 & t < 0 \ 2 & t \ge 0 \end{cases}$$

(The $\sin(t)$ branch gets completely wiped out — multiplied by zero.)

**Physical meaning:** multiplying by $u(t)$ acts like a **switch that turns on at $t=0$** — it discards/mutes everything before $t=0$ and passes through everything from $t=0$ onward unchanged. This is exactly how you'd model "flipping on a device" or "starting to record" at $t=0$.

**4.** Running maximum: $y[n] = \max_{k\le n} x[k]$, with $x = {3,-1,5,5,2,7}$ for $n=0,\dots,5$.

(a)

|$n$|0|1|2|3|4|5|
|---|---|---|---|---|---|---|
|$x[n]$|3|−1|5|5|2|7|
|$y[n]$|3|3|5|5|5|7|

(b) **No**, $y[n]$ cannot be computed from $x[n]$ alone — it requires the _entire history_ $x[0], x[1], \dots, x[n]$. This system has unbounded memory.

It also proves $y[n]$ **cannot** be written as $y[n] = f(x[n])$ for any single-variable function $f$: look at $n=4$, where $x[4]=2$, giving $y[4]=5$. But suppose instead the sequence had been $x = {1,-1,0,0,2,7}$ — here $x[4]=2$ again, but now $y[4] = \max(1,-1,0,0,2) = 2$. The _same_ input value ($x[4]=2$) produced _two different_ outputs ($5$ vs $2$) depending on what happened earlier. A true function can never do that (same input → same output, always) — so this confirms the system genuinely depends on the whole trajectory, not just the instantaneous value.
