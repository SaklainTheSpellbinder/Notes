# 1. Ordinary 1D linear convolution

Question could say:

> Given two finite signals, calculate their linear convolution using your FFT.

Use:

```python
def linear_conv(a, b, engine):
    L = len(a) + len(b) - 1
    N = next_power_of_two(L)

    pa = np.zeros(N, dtype=complex)
    pb = np.zeros(N, dtype=complex)

    pa[:len(a)] = a
    pb[:len(b)] = b

    A = engine.transform(pa)
    B = engine.transform(pb)

    y = engine.inverse(A * B).real

    return y[:L]
```

Key rule:

$$
\boxed{L=L_a+L_b-1}
$$

and pad before FFT.

# 2. Circular convolution

If they explicitly say **circular convolution of length \(N\)**:

```python
A = engine.transform(a)
B = engine.transform(b)

y = engine.inverse(A * B).real
```

No extra padding intended to eliminate wrap-around.

Difference:

$$
\boxed{\text{no padding} \Rightarrow \text{circular convolution}}
$$

$$
\boxed{\text{sufficient padding} \Rightarrow \text{linear convolution}}
$$

This is one of the most important distinctions in the offline itself.

# 3. Given output + one signal, find the other signal

This is a very plausible extension.

Suppose:

$$
y=x\circledast h.
$$

You know \(y\) and \(x\), but need \(h\).

Then:

$$
Y=XH
$$

so:

$$
\boxed{H=Y/X}.
$$

Code:

```python
X = engine.transform(x)
Y = engine.transform(y)

H = Y / X

h = engine.inverse(H).real
```

If they ask for original \(x\) instead:

```python
X = Y / H
x = engine.inverse(X).real
```

This is exactly deconvolution.

# 4. Safer deconvolution

If the question mentions noise or division by zero:

```python
eps = 1e-8

X = (
    Y * np.conj(H)
    / (np.abs(H)**2 + eps)
)

x = engine.inverse(X).real
```

Remember:

$$
\boxed{
\hat X=
\frac{YH^*}{|H|^2+\epsilon}
}
$$

# 9. Frequency-domain low-pass filtering

Since Task B blur is fundamentally low-pass filtering, they could ask you to directly manipulate the spectrum.

Example:

```python
X = engine.transform(x)
```

Keep only low-frequency bins.

For an \(N\)-point real signal, a simple mask might be:

```python
Y = np.zeros_like(X)

cutoff = 5

Y[:cutoff+1] = X[:cutoff+1]
Y[-cutoff:] = X[-cutoff:]
```

Then:

```python
filtered = engine.inverse(Y).real
```

Why keep both ends?

Because negative-frequency bins of the DFT lie near:

$$
N-1,N-2,\ldots
$$

# 10. High-pass filtering

Opposite idea:

```python
Y = X.copy()

cutoff = 5

Y[:cutoff+1] = 0
Y[-cutoff:] = 0

high = engine.inverse(Y).real
```

This removes slow variation and preserves rapid changes.

For images, high frequencies correspond strongly to:

* edges,
* texture,
* fine detail.

So a question might say:

> extract edges or fine details using the DFT.

# 11. Remove one sinusoidal noise frequency

Very plausible FFT application.

Suppose a signal has unwanted periodic interference.

Calculate:

```python
X = engine.transform(x)

mag = np.abs(X)

k = np.argmax(mag[1:]) + 1
```

If real-valued signal, also remove its conjugate partner:

$$
N-k.
$$

```python
X[k] = 0
X[-k] = 0

clean = engine.inverse(X).real
```

Why both?

For real signals:

$$
X[N-k]=X[k]^*.
$$

If you delete only one side, the reconstructed signal can become complex.

# 12. Find dominant frequency

Given:

```python
X = engine.transform(x)

k = np.argmax(np.abs(X))
```

That gives the strongest bin.

If DC should be ignored:

```python
k = np.argmax(np.abs(X[1:])) + 1
```

If sampling frequency is \(f_s\):

$$
\boxed{
f_k=\frac{k}{N}f_s
}
$$

for positive-frequency bins.

If:

$$
k>N/2,
$$

interpret signed frequency:

$$
k-N.
$$

So:

```python
signed_k = k if k <= N//2 else k - N

frequency = signed_k * fs / N
```

# 13. Detect time shift directly from DFT phase

This is a harder variation.

If:

$$
y[n]=x[(n-m)\bmod N],
$$

then:

$$
\boxed{
Y[k]=X[k]e^{-j2\pi km/N}
}
$$

So shifting in time does **not** change magnitude:

$$
|Y[k]|=|X[k]|.
$$

It only changes phase.

Therefore if they show two spectra with identical magnitudes but linearly changing phase, one signal may simply be shifted.

Cross-correlation is generally easier for coding, but know this property.

# 14. Circular time-shift property

This is one FFT property you should absolutely know:

$$
x[(n-m)\bmod N]
\longleftrightarrow
X[k]e^{-j2\pi km/N}.
$$

Python shift:

```python
shifted = np.roll(x, m)
```

Equivalent spectrum:

```python
k = np.arange(N)

Y = X * np.exp(
    -2j * np.pi * k * m / N
)
```

Then:

```python
shifted2 = engine.inverse(Y)
```

should match `np.roll(x, m)`.

This could easily be turned into an online question.

# 15. Frequency-shift / modulation property

Another useful one:

If:

$$
y[n]
=
x[n]e^{j2\pi mn/N},
$$

then:

$$
\boxed{
Y[k]=X[(k-m)\bmod N].
}
$$

So multiplication by a complex sinusoid in time shifts the spectrum.

Python:

```python
n = np.arange(N)

y = x * np.exp(
    2j * np.pi * m * n / N
)
```

This moves frequency content by \(m\) bins.

# 16. Time reversal

For circular reversal:

$$
y[n]=x[(-n)\bmod N].
$$

DFT property:

$$
\boxed{
Y[k]=X[(-k)\bmod N].
}
$$

Python signal reversal must be handled carefully.

Ordinary:

```python
x[::-1]
```

gives:

$$
[x[N-1],...,x[0]],
$$

while circular \(x[-n]\) corresponds to:

```python
np.roll(x[::-1], 1)
```

for many indexing conventions.

Know the distinction.

---

# 17. Conjugation property

If:

$$
x^*[n]
$$

then:

$$
\boxed{
DFT\{x^*[n]\}=X^*[(-k)\bmod N].
}
$$

For a **real signal**:

$$
x=x^*,
$$

so:

$$
\boxed{
X[N-k]=X[k]^*
}
$$

which is conjugate symmetry.

This is why real signals have mirrored magnitude spectra.

# 20. Zero-padding and what it does NOT do

Very likely conceptual trap.

Zero-padding does **not** add new signal information.

For example:

```python
xpad = np.zeros(16)
xpad[:len(x)] = x
```

The underlying DTFT is unchanged; you simply sample it at more frequency locations with a longer DFT.

For convolution, however, zero-padding has an additional critical role:

$$
\boxed{\text{prevents circular aliasing}}
$$

when padded to at least:

$$
L_x+L_h-1.
$$

These are two related but distinct uses.

```python

```

For even \(N\), Nyquist bin \(N/2\) is special.

# 29. Why convolution theorem is useful

For direct 1D convolution:

$$
O(N^2).
$$

FFT:

$$
FFT + FFT + multiply + IFFT
$$

approximately:

$$
\boxed{O(N\log N)}.
$$

For an image:

direct spatial with \(K\times K\) kernel:

$$
O(N^2K^2).
$$

row-column FFT:

$$
O(N^2\log N).
$$

Your benchmark is specifically designed to expose these complexity differences. 

---

# 30. One subtle online possibility: FFT is not always faster

Your benchmark showed this.

For a small kernel:

$$
3\times3,
$$

direct convolution can beat FFT because FFT has setup overhead.

For large kernels:

$$
31\times31,\;63\times63,
$$

FFT becomes advantageous.

So if asked:

> Which method should we use?

Answer:

* small local kernel → direct often faster;
* large kernel/image → FFT often wins;
* asymptotically FFT is better, but constants matter.

# Properties I would memorize before the online

These are the highest-value DFT properties for your lab:

| Property             | Time / spatial domain      | Frequency domain          |
| -------------------- | -------------------------- | ------------------------- |
| Linearity            | \(ax+by\)                  | \(aX+bY\)                 |
| Circular convolution | \(x\circledast h\)         | \(XH\)                    |
| Correlation          | \(x\star y\)               | \(X^*Y\)                  |
| Circular shift       | \(x[(n-m)_N]\)             | \(Xe^{-j2\pi km/N}\)      |
| Modulation           | \(xe^{j2\pi mn/N}\)        | spectrum shifted by \(m\) |
| Real-signal symmetry | real \(x[n]\)              | \(X[N-k]=X[k]^*\)         |
| DC                   | \(\sum x[n]\)              | \(X[0]\)                  |
| Parseval             | energy in time             | energy in frequency       |
| Deconvolution        | recover \(x\) from \(x*h\) | divide by \(H\)           |

If I had to reduce even further, the four most important are:

$$
\boxed{x\circledast h\leftrightarrow XH}
$$

$$
\boxed{x\star y\leftrightarrow X^*Y}
$$

$$
\boxed{x[(n-m)_N]\leftrightarrow Xe^{-j2\pi km/N}}
$$

$$
\boxed{x\text{ real}\Rightarrow X[N-k]=X[k]^*}
$$

# The 10-second question-decoding strategy

When you see the online problem, find the operation:

**“combine every pair / multiply polynomial / blur”**

$$
\Rightarrow\boxed{\text{convolution}}
$$

**“shift / align / locate”**

$$
\Rightarrow\boxed{\text{correlation}}
$$

**“was convolved, restore/decrypt”**

$$
\Rightarrow\boxed{\text{deconvolution}}
$$

**“remove smooth part / preserve edges”**

$$
\Rightarrow\boxed{\text{high-pass}}
$$

**“smooth/remove noise”**

$$
\Rightarrow\boxed{\text{low-pass}}
$$

**“periodic noise / dominant oscillation”**

$$
\Rightarrow\boxed{\text{inspect magnitude spectrum}}
$$

Then decide:

$$
\boxed{\text{linear or circular?}}
$$

If linear, immediately write:

```python
L = len(a) + len(b) - 1
N = next_power_of_two(L)
```

That single decision prevents a large fraction of Fourier-lab mistakes.
